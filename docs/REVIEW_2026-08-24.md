# STP Token Updater – first implementation review

Date: 2026-08-24

This review compares the first implementation against the project requirements and current Home Assistant APIs. The public product name is **STP Token Updater** (`STP = Sponsor Token Provider`). Provider-specific protocol identifiers remain internal where technically required.

## Review result

The first implementation was not yet install-ready. The following issues were identified and corrected before the repository reset.

## Confirmed issues fixed

### Config Flow auth selector

The password authentication constant was used but not imported, which could raise `NameError` while building the setup form.

### Sensor descriptions

`SensorEntityDescription` instances used positional arguments incompatible with the current Home Assistant API. All descriptions now use explicit keyword arguments.

### Repairs API

The first implementation imported the wrong Repairs issue-registry path. It now uses `homeassistant.helpers.issue_registry`.

### Renewal checkpoint repetition

If a due checkpoint found no newer candidate, or if the public source failed, the checkpoint could remain due on every normal five-minute status refresh. Scheduler checkpoint progress is now tracked separately from actual token POST attempts.

### Write error handling

Only transport/connection failures are treated as uncertain writes followed by readback. Definite authentication, rate-limit or API rejections propagate to the coordinator so the appropriate status/Repair path can be used.

### File-managed token validity

A file/YAML-managed token is not automatically invalid. Token validity now reflects authorization and expiry; the file source is reported separately as a configuration/update conflict.

### CI coverage

HACS, Hassfest and pytest workflows are present. Home Assistant smoke tests are intended to protect the Config Flow, sensor descriptions and Repairs imports from API compatibility regressions.

## Test-safety requirement

Automated tests must not issue a real sponsor-token write. Live write acceptance testing is explicit, uses a strictly newer candidate, and performs delayed read-after-write verification without blind retry after a transport timeout.

## Public anonymization / branding

Visible product/UI branding is **STP Token Updater**. Provider-specific values are retained only where they are required by the upstream protocol or by the existing Home Assistant domain/storage identity.
